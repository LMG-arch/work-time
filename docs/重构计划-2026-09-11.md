## 0. 目标与验收标准

### 0.1 总目标
让应用只剩**一套 UI 外壳、一套数据真值、一套能力实现**：
1. 删除经典遗留外壳（`.app` 死 DOM）与其渲染层；
2. Vue 组件不再通过 `window.*` 反向依赖经典层的数据镜像与渲染器；
3. 保留的能力（原生桥、节假日/农历、云同步、通知调度、图片导出）改为**显式模块 import**；
4. 同类能力只允许一份实现（提示、主题、存储写入者、日历渲染）。

### 0.2 量化验收指标（可机械核对）

| 指标 | 当前 | 目标 |
|---|---|---|
| `src/index.html` 行数 | 341（其中 `.app` 死壳 121–338） | ≤ 130 |
| 经典渲染层代码 | ≈ 2,030 行（renderer 746 / social 721 / calendar 260 / settings 198 / todos 106） | 0（能力迁移后删除） |
| `src/shims.js` 规模 | 209 行 / 148 个 `window.*` 绑定 | ≤ 60 行 / ≤ 30 绑定 |
| Vue 侧依赖的 `window.*` 名称 | 约 40 种 | ≤ 12 种（仅原生桥封装） |
| `getElementById(...).prop` 裸写 | lifeEngine 69 处；经典层 22 处 | lifeEngine 0（走统一助手）；经典层随层归零 |
| DOM 中 `.day-cell` 数量 | 70（35 个属隐藏经典网格） | 35 |
| 每个存储键的写入者 | `calendar-theme` 2 个、`calendar-nav-items` 3 个 | 各 1 个 |
| 同类能力实现份数 | 提示 2 / 主题令牌 2 / 日历渲染 2 / 外壳 2 | 各 1 |

### 0.3 验收方式
- 每阶段：`vite build` + `capacitor sync` + gradle 签名 APK + 发布小版本 + 冒烟矩阵（见 §6）
- 阶段 4 追加：真机冷启动 ×3、原生通知定时触发实测、云同步往返

### 发布流程修正（v3.17.39/v3.17.40 暴露）
1. **`gh release create` 不会推送本地 tag**：远端若不存在该 tag，GitHub 会**在默认分支 HEAD 上新建 tag**（本项目默认分支停在 v3.17.22，导致 v3.17.39/v3.17.40 的远端 tag 一度指向陈旧提交）。
   → 规则：**每阶段先 `git commit` → `git tag` → `git push origin <branch> <tag>`，再 `gh release create`**；发布后执行 tag 审计：
   ```bash
   for t in vX.Y.Z ...; do L=$(git rev-parse "$t^{commit}"); R=$(git ls-remote --tags origin "$t" | cut -f1);
     [ "$L" = "$R" ] && echo "$t OK" || echo "$t MISMATCH"; done
   ```
2. **阶段 2 的代码未单独提交**（并入 `497c34a`），故 v3.17.39 无独立提交 → 已将 tag 置于包含阶段 2 代码的提交上并备注。规则：**每阶段结束必须立即提交**，不可跨阶段累积。
3. 修正记录：`v3.17.39` / `v3.17.40` 远端 tag 已强制更新至 `497c34a`（含阶段 2 与阶段 3 第一批代码）。
